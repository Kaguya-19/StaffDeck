# SD 正常 Harness turn 使用 PD 模型公共 Port

源基线 SD `23d9319d2a813dd8b5d2e68b2165da253fd893ce`，对照固定 PD `8e210942fda77bff534d4b851be7027f1fee2d17` 与 Harness 依赖 `0a53fb55`。本提交在 SD 的认证固定 PD domain binding 下选择当前 PD profile 的唯一可用默认模型，并通过现有公共 Port 完成正常 chat、Knowledge 对话和 SOP turn 的原 Harness 请求。目录可含其他可用模型；同一默认项重复、不可用或与 defaultSelection 不符均拒绝。`PilotDeckHarnessModel` 仅为本轮非持久选模值；没有 SD `ModelConfig`、第二 provider 或失败自动回退。Gateway 仍持固定 tenant/actor/agent/PD user 与服务凭据，`engine_host` 仍先通过原 `resolve_staff` 进行 staff.use/PEP，Knowledge 与 SOP 使用原领域状态和可见性规则。

`pilotdeck_harness_model.select_harness_model(context, model_id)` 接受已授权 `SourceContext` 与可选显式 PD `provider/model` ID，拒绝固定身份不匹配及旧 SD model_config_id。它以固定 Bearer、同一 principal 调 `POST /api/module-host/describe`，要求列出 `list_model_catalog`、`model_prepare`、`model_stream`，再用 `list_model_catalog {}` 的 `data[]` 与 `defaultSelection` 选当前 profile 唯一可用默认项。`prepare_model_request(selection, canonical_request)` 以 `requestId`、`modelId`、`request` 调认证 `model_prepare`，校验回执的 selection/request；`stream_model_events` 用同一组三字段调 `model_stream`，校验 NDJSON 与选中 provider/model 响应头。`pilotdeck_model_wire.canonical_request/openai_chunks` 映射 Harness OpenAI wire 与 PD canonical messages/tools/events；无法同语义表示的输入显式 400。prepare 的 400/503 在模型流响应前返回，流错误/断流/缺 message_end/非 stop 终态不能成为成功的 Harness completion；取消或固定 activation 撤销显错。`timeout_seconds` 是 SD 本地 HTTP 等待，只作内部 `dataclasses.replace` 派生值，不进入 PD 选模或 canonical payload。Memory JSON 与 Knowledge 原文档/索引模型路由调用同一公开 PD Port；域内 PEP、原路由失败处理未改。

不要求整合修改 `modules.js`、浏览器 adapter 或 PD core；这组 SD hunk 可直接整合。运行方需沿既有正式 startup 将 `PILOTDECK_DOMAIN_HOST_ENABLED=true`、固定身份 tuple、Gateway URL/token path 与 PD user 绑定；未绑定及不匹配均显错。PD Gateway 必须公开上述三个 model Port operation 及 describe，不需要新增 scope。账户 secret 仅留在服务端启动输入。整合消费本 SD 提交即可，没有新增 root 回调形状。
